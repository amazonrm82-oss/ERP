# מערכת CRM כ-SaaS

מערכת CRM רב-ארגונית בעברית לעסקים קטנים ובינוניים. כל לקוח נרשם לבד, פותח ארגון, בוחר חבילה ומוסיף עובדים.

פרויקט חדש ועצמאי. הוא אינו קשור לאף מערכת אחרת ואינו משתמש במסד נתונים או במפתחות של פרויקט אחר.

המאגר הזה הכיל עד 6 באוקטובר 2026 מערכת ERP אחרת. הקוד הישן שלה שמור בענף `backup/erp-before-crm-2026-10-06`. אין להריץ את המיגרציות של המערכת הזאת על פרויקט ה-Supabase של ה-ERP הישן: צריך פרויקט Supabase חדש וריק.

## מה בנוי כרגע

- **מסד נתונים** (`supabase/migrations`): ארגונים, משתמשים, תפקידים וצוותים, הזמנות, חבילות ומכסות, לידים, אנשי קשר, חברות, עסקאות ופייפליינים, משימות, ציר זמן, שדות מותאמים, יומן ביקורת, אירועים לאוטומציות והתראות. הבידוד בין ארגונים נאכף במסד עצמו.
- **אפליקציה** (`src`): הרשמה וכניסה, הקמת ארגון, מעטפת עם תפריט, לידים (רשימה, יצירה, כרטיס, ציר זמן, המרה), אנשי קשר, לוח עסקאות, ומסך "היום שלי".
- **בדיקות** (`tests/db`): 65 בדיקות אוטומטיות על המסד, בעיקר בידוד בין ארגונים והרשאות.

מה שעוד לא נבדק: האפליקציה מול פרויקט Supabase אמיתי. זה הצעד הראשון ב-backlog.

## הרצה מקומית

```bash
npm install
cp .env.example .env.local     # ולמלא את פרטי פרויקט ה-Supabase החדש
npm run dev
```

## בדיקות

```bash
npm run lint && npm run typecheck && npm run build
npm run db:test:start          # מסד PostgreSQL זמני על המחשב, לא נוגע בשום פרויקט
npm run test:db
```

בדיקות המסד מסרבות לרוץ מול כל כתובת שאינה מקומית.

## חיבור לסביבה אמיתית

1. לפתוח פרויקט **חדש** ב-Supabase (לא להשתמש בפרויקט קיים).
2. להריץ את המיגרציות מהתיקייה `supabase/migrations` על הפרויקט החדש.
3. להעתיק את כתובת הפרויקט ואת המפתח הציבורי ל-`.env.local`, ובהמשך למשתני הסביבה ב-Vercel.
4. לפתוח פרויקט **חדש** ב-Vercel ולחבר אותו למאגר הזה.
