# FXD-08: העברת ההרחבה pg_net מהסכמה הציבורית

הקובץ הזה מיועד להדבקה ידנית ב-SQL Editor של Supabase. כך אישרת ב-18 באוקטובר: קודם בדיקה מקומית, וצעדי חזרה כתובים מראש.

## מה זה עושה ולמה

- היועץ של Supabase מזהיר שההרחבה `pg_net` רשומה בסכמה הציבורית (`public`). הקובץ רושם אותה מחדש בסכמה `extensions`.
- את `pg_net` אי אפשר להזיז במקום, ולכן הקובץ מסיר אותה ומתקין אותה מחדש באותה גרסה. כל זה קורה בצעד אחד: או שהכל עובר, או ששום דבר לא משתנה.
- **מה נשאר כמו שהיה:** הפונקציות של ההרחבה נשארות בסכמה `net`. שתי הפונקציות שלנו שמשתמשות בה הן ההתראות לטלפון (`app.dispatch_push`) וניקוי הקבצים הלילי (`app.cleanup_files`). שתיהן קוראות לה בשם המלא `net.http_post` ובודקות רק שהיא מותקנת, ולכן ממשיכות לעבוד. בדיקה 167 שומרת על זה גם בהמשך.
- **מה הולך לאיבוד:** בקשות שממתינות לשליחה באותו רגע, כלומר כמה שניות של "התעוררות" של ההתראות לטלפון. הריצה של הדקה הבאה שולחת אותן שוב. בגלל זה מריצים בשעה שקטה.
- **מה נבדק אצלי:**
  - הקובץ רץ על מסד בדיקה בלי pg_net ולא שינה כלום.
  - באותו קובץ, עם הרחבה אחרת במקום pg_net, ההעברה וגם החזרה עבדו, וכל אחת מהן פעמיים.
  - כשמשהו תלוי בהרחבה, המחיקה נדחתה ושום דבר לא השתנה.
- **מה לא נבדק:** pg_net עצמה לא קיימת במסד הבדיקה שלי.

## מתי

בשעה שקטה, למשל אחרי 23:00. לא בין 01:00 ל-05:00 שעון UTC (03:00–08:00 בשעון ישראל), כי אז רצות המשימות הליליות.

## לפני ההדבקה (קריאה בלבד)

```sql
select n.nspname as pg_net_schema, e.extversion as version
  from pg_extension e join pg_namespace n on n.oid = e.extnamespace
 where e.extname = 'pg_net';
```

אמורה לחזור שורה אחת עם `public`. רשום לעצמך את הגרסה.

## מה להדביק

את הקובץ `supabase/manual/fxd08_pg_net_move.sql` כולו, בהדבקה אחת, ואז Run.

**איך נראית הצלחה:** בתוצאה מופיעה שורה אחת עם `extensions`, ועם אותה גרסה שרשמת.

אם מופיעה שגיאה, שום דבר לא השתנה. לא מנסים שוב, ושולחים לי את הטקסט שלה.

## איך בודקים שהכל עובד אחרי ההעברה

1. **הפונקציה של ההרחבה קיימת** (קריאה בלבד):

   ```sql
   select count(*) from pg_proc where proname = 'http_post' and pronamespace = 'net'::regnamespace;
   ```

   אמור לחזור 1 או יותר.

2. **התראות לטלפון:** באפליקציה, נכנסים ל"הגדרות > החשבון שלי" ולוחצים על "שליחת התראת בדיקה אליי". ההתראה אמורה להגיע לטלפון תוך דקה.

   אפשר גם לבדוק ב-SQL שהבקשה יצאה (קריאה בלבד):

   ```sql
   select id, status_code, error_msg, created from net._http_response order by created desc limit 5;
   ```

   בשורה החדשה צריך להופיע `status_code` 200, ובלי `error_msg`.

3. **ניקוי קבצים:** אחרי הלילה הבא בודקים (קריאה בלבד):

   ```sql
   select d.status, d.return_message, d.start_time
     from cron.job_run_details d join cron.job j on j.jobid = d.jobid
    where j.jobname in ('crm-file-cleanup', 'crm-notifications')
    order by d.start_time desc limit 10;
   ```

   בעמודה `status` אמור להופיע `succeeded`. אחרי כמה ימים מספר הקבצים שממתינים לניקוי אמור לרדת:

   ```sql
   select count(*) from app.orphan_files;
   ```

4. **אזהרת היועץ:** האזהרה על `pg_net` בסכמה הציבורית אמורה להיעלם. המוביל מריץ את הבדיקה של היועץ.

## חזרה אחורה (רק אם משהו נשבר)

1. מדביקים את `supabase/manual/fxd08_pg_net_rollback.sql` כולו, ואז Run.
2. בתוצאה צריך להופיע `public`.
3. בודקים שוב את סעיפים 1–3 שלמעלה.
4. כותבים לי מה ראית, כדי שנבין מה נשבר לפני שמנסים שוב.

גם החזרה מאבדת בקשות שממתינות באותו רגע, ומותר להריץ אותה פעמיים.

כשסיימת, כתוב לי "הרצתי".
