## החלטות פתוחות

- [ ] **שוק יעד:** לאשר ישראל בלבד בשלב הראשון.
- [ ] **ספק סליקה למנויים:** Tranzila, PayPlus, Cardcom או SUMIT. חוסם את מודול החיוב.
- [ ] **ספקי חשבוניות ראשונים:** אילו שניים לחבר קודם.
- [ ] **מיקום הנתונים:** באיזה אזור ייפתח פרויקט ה-Supabase. לבדוק אילו אזורים מוצעים, ולשאול עורך דין אם לקוחות היעד דורשים אחסון בארץ.
- [ ] **נראות המאגר:** המאגר `ERP` ציבורי ב-GitHub. להחליט אם להפוך אותו לפרטי.
- [ ] **שם המוצר ודומיין.** כרגע בקוד: `APP_NAME = "CRM"` בקובץ `src/lib/app.ts`.
- [ ] **ישות עסקית** שתחתיה המוצר נמכר, ורואה חשבון.
- [ ] **עורך דין:** תנאי שימוש, מדיניות פרטיות, הסכם עיבוד מידע, והשאלות שסומנו באפיון כלא מאומתות.
- [ ] **ספק אימייל (SMTP).** חוסם שליחת הזמנות באימייל ותזכורות. בנוסף, שרת האימייל המובנה של Supabase שולח רק לכתובות של חברי הצוות בפרויקט ה-Supabase, ובמכסה של הודעות בודדות בשעה. לכן לקוחות אמיתיים לא יקבלו אימייל אימות עד שמחברים ספק (למשל Resend, Postmark או SendGrid) תחת Authentication → Emails → SMTP Settings. נרשם ב-6 באוקטובר 2026.
- [ ] **Facebook Lead Ads (סעיף 4 ב-BACKLOG).** נדחה עד שיהיו אימות עסק ב-Meta ואפליקציית Meta עם הרשאת leads_retrieval. עד אז אפשר לחבר לידים מפייסבוק דרך Zapier או Make אל ה-webhook. נרשם ב-6 באוקטובר 2026.
- [ ] **אימות עסק ב-Meta** לצורך לידים מפייסבוק ו-WhatsApp. כדאי להתחיל מוקדם.

## החלטות טכניות שהתקבלו

- מסד נתונים אחד משותף לכל הארגונים, עם בידוד ב-Row Level Security.
- קישורים בין טבלאות עסקיות הם מפתחות זרים מורכבים שכוללים את מזהה הארגון.
- סכומים נשמרים באגורות כמספר שלם. זמנים נשמרים ב-UTC.
- שדות מותאמים נשמרים בעמודת JSON בכל רשומה, והגדרותיהם בטבלת `field_definitions`.
- כל שינוי ברשומה עסקית נכתב לטבלת `outbox_events`. מנוע האוטומציות, ה-webhooks וההתראות יקראו ממנה.
- רק הבעלים ממנה מנהלי מערכת, גם בהזמנה וגם בשינוי תפקיד (מיגרציה 0006). מנהל מערכת מנהל את שאר המשתמשים.
- עד שיש ספק אימייל, הזמנה היא קישור שהמנהל מעתיק או שולח ב-WhatsApp. הקישור מוצג פעם אחת, תקף 7 ימים, ומתאים רק לכתובת שהוזמנה.
- קליטת לידים: פנייה מבחוץ מגיעה לנתיב שרת, והוא קורא לפונקציה אחת במסד (`intake_submit`) עם מפתח השירות. זה המקום היחיד שמשתמש במפתח השירות. הטוקן של טופס ציבורי אינו סוד, כי הוא מופיע בקוד ההטמעה. הטוקן של webhook הוא סוד.
- אפשר להטמיע ב-iframe רק את הטופס הציבורי (`/f/...`). שאר האפליקציה חסומה להטמעה (`frame-ancestors 'none'`).
- פעולות רגישות (הקמת ארגון, הזמנה, הצטרפות, העברת בעלות, המרת ליד) הן פונקציות במסד ולא כתיבה ישירה לטבלאות.
